## 1. Загальна методологія промпт-інжинірингу

У рамках розробки системи було реалізовано ітеративний трикроковий підхід до проектування інструкцій для LLM:

* **Ітерація v1 (Наївний базовий підхід):** короткий вільний запит без чіткої ролі аналітика, без вихідних рамок і обмежень на структуру відповіді. Мета — оцінити поведінку «з коробки» та виявити схильність моделі до суб'єктивних інтерпретацій чи спекуляцій.
* **Ітерація v2 (Рольові обмеження та шаблон виводу):** закріплення за моделлю вузької аналітичної ролі (Senior Product Analyst / CPO), явна директивна заборона вигадування чисел (спиратися виключно на наданий JSON-профіль), структуризація відповіді за попередньо визначеними розділами.
* **Ітерація v3 (Structured Output: XML Context + Валідний JSON):** перехід на сучасний промисловий стандарт промпт-інжинірингу за рекомендаціями Google та Anthropic:
  1. Розділення інструкцій за допомогою явних XML-тегів (`<context>`, `<rules>`, `<dataset_profile>`, `<instructions>`), що запобігає «змішуванню» системних правил із самими даними.
  2. Примусова генерація валідного JSON (`response_mime_type="application/json"`), поля якого відповідають строгій схемі.
  3. Детермінований пост-процесинг на Python: розпарсений JSON перетворюється спеціальною функцією у читабельний, красивий текст для людини, що забезпечує ідеальний баланс між машинною строгістю та зручністю для користувача.

Завдяки функції `format_v3_to_human_text` вивід читається як готовий корпоративний документ.

### Ключовий висновок роботи:
Поєднання детермінованих розрахунків на Python із XML/JSON промпт-інжинірингом дозволяє пришвидшити рутинну роботу з отриманням . Модель не займається обчисленнями, а фокусується на пошуку смислових взаємозв'язків та перетворенні технічних агрегатів на зрозумілі бізнес-рішення.
